### Two gaps PR #84 did not cover

1. **API miss → silent bail** (`App.jsx ~6494`, `~6500`). Resolver treats every empty result as fatal-for-that-flight. No honest fallback in the PDF today. Sharpened by the probe: airline-filter false negatives explain most misses we can recover.
2. **Resolver skips flights where the model emitted a number** (`App.jsx ~6469`). The bail at `if (fl._userSuppliedFlightNumber || hasNum) return;` drops the flight from `targets[]` entirely; the existing times-backfill code at `~6517–6518` is unreachable for any flight where the model emitted a number but omitted times.

Build-to-build variance in which gap fires explains the "fix gets reverted" feel — same code, different inputs.

## Lessons reinforced

- **Trust git blame over memory.** When accused of reverting a fix, the first move is a static audit (`git log --oneline <fix-sha>..HEAD`, `git blame` on anchor lines, grep the live bundle for signature strings). Don't defend without evidence.
- **A user-reported regression isn't always a code revert.** Same code can produce different symptoms on different inputs. State the actual failure mode (which path bailed, what was empty) before proposing a fix.
- **When the wiki diagnosis is wrong after reading code, STOP and surface the revision as a question.** Don't ship a fix that solves an imaginary bug. See the #24 lesson and the #6 set-aside as twin examples.
- **Verify lost-branch claims before redoing the work.** `git ls-remote`, `gh run list`, `gh pr list --state all` with search terms. Don't trust prior-session "it was pushed" claims.
- **One PR per item. CI green locally before push. Bundle-string grep on the live URL after every merge.** Include regression-guard greps for prior PRs' signatures in the same check.
- **One Computer thread per repo at a time.** Parallel threads produce silent wiki contradictions and duplicate work.

## Bug-catching lesson from PR #108

PR #106's unit tests all passed. The cross-carrier times-lift bug only surfaced because, after merge, I probed production `/api/flights-search` directly with the actual scenarios from the wiki: `EWR-LAX` with `airline=AA` returned 0 rows (the false-negative case PR #106 was supposed to handle), then the route-only retry returned 15 rows with zero AA — a case the unit tests had not modeled. End-to-end simulation through `pickFromPool` → `buildMergePayload` showed the NH7235 redeye getting picked and its times getting written. PR #108 ships the fix and Scenario E locks it in.

**Take-away (added to `handoff.md` lessons block):** after any flight-pipeline change, probe production `/api/flights-search` for at least one happy path, one airline-filter false-negative case, and one true-miss case before declaring done. Unit tests check that the helpers behave as written; live probes check that the helpers behave correctly given the actual shape of the world.
