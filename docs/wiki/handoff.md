## 2. What this app is

Luxury-tier travel-planning web app, one bundle, two+ surfaces:

- **`/`** — full itinerary build. Three-step wizard (Essentials → Details → Your plan) turning a
  free-text trip brief into a day-by-day itinerary with hotels, restaurants, activities, ground
  transport, cost estimate, backup plans, a phone-ready reference sheet, and a PDF/web export.
- **`/find`** — quick single-screen lookup for restaurants/activities in a given location, with an
  automatic "locals' picks" pass.
- **A household passphrase gate in front of both**, added 2026-09-07 (see §7 — this is new since
  the last handoff rewrite and not yet documented anywhere else).

## 3. HARD RULES — never violate these regardless of what else changes

All sourced from `CLAUDE.md` (root of repo), which is the actual binding instruction set for any
agent working here. This section is a condensed index, not a replacement — read the full file
before touching venue data, dates, prompts, or PDF export.

1. **Branch/deploy:** `master` is production (deploys to routesmith.ai). `main` deploys nowhere —
   never push only there. Base feature branches off `master`.
2. **Venue verification (HARD RULE):** never emit a venue name/address/phone/hours/price/weekday
   that hasn't been verified against an external source or computed in code. Existence +
   `business_status` MUST be checked via Google Places (New) Place Details before export; closed
   venues are blocked and replaced, never flagged-and-shipped. Day-of-week, durations, time math,
   and sums are COMPUTED IN CODE, never model-generated. Prose grounding (Perplexity/Reddit) is
   qualitative context only, never the basis for existence/status/address/phone/hours.
3. **Verification Discipline (the user's explicit, repeated, angry complaint — 2026-07-01 and
   2026-08-01):** *"Never say a UI change works without running it in a browser and capturing what
   you see."* Code compiling, a passing build, a test that only imports a function — none of that
   is evidence a UI feature works. The only evidence is a screenshot/log from the actual running
   app. **"Verified locally" ≠ "verified in production"** — say exactly which one was checked, never
   let one imply the other. **This sandbox's egress policy blocks `routesmith.ai` outright** (403 on
   CONNECT, confirmed 2026-08-01) — check proxy status before promising to "pull up the browser and
   check prod"; if unreachable, say so plainly, don't guess dressed up as an answer.
4. **Scope discipline:** read real code before editing, trace actual call sites, don't assume.
   Change only what's asked. Never hardcode secrets (`env.*` only). Show diffs before deploying —
   deploy is the maintainer's call. The streaming `/api/build` endpoint is delicate (rewritten
   2026-05-24 for a `waitUntil` bug) — no new post-stream blocking work there.
5. **PDF save is share-first, not `pdf.save()`** — all three PDF call sites route through
   `savePdfShareFirst()`. iOS 13+ Safari silently writes `pdf.save()` output to Files/Downloads
   with no chooser; `navigator.share({files})` restores the picker. Feature-detected via
   `canShare({files})`, never user-agent sniffing. Do not "simplify" this back.
6. **A `flags:"block"` venue must never reach the PDF exporter** — the pre-export gate is the last
   line of defense, not optional even on "Export anyway."
7. **AVAILABLE CONNECTORS (Tripadvisor/Resy/Civitatis/Uber/Cloudflare/Railway, added 2026-08-28) are
   session-side agent tools only** — NOT reachable from the deployed server code. Do not describe
   production verification as improved by a connector being present in a chat session; that
   requires real Cloudflare Pages secrets + new `functions/api/` code, a separate scoped task.
8. **ESLint baseline: 0 errors, ~13-14 warnings** in `src/App.jsx` as of the last few CLAUDE.md
   entries (count has crept slightly as features were added — check current count with
   `npm run lint`, not this number, before adding code).

## 5. Flag taxonomy (authoritative, condensed)

Full table with descriptions lives in `CLAUDE.md` — reproduced here as a quick index. Emitted by
`/api/places-verify-batch`, `functions/api/find.js`, and the deterministic client-side validators;
consumed by the pre-export gate.

**Places-sourced (block):** `CLOSED_PERMANENTLY`, `CLOSED_TEMPORARILY`, `NOT_FOUND`,
`WRONG_LOCATION`, `PACING_IMPOSSIBLE`, `CLOSED_ON_THIS_DAY` (block only when the item is an
*anchor* — a reservation/timed-entry; warn otherwise).

**Places-sourced (warn/info):** `UNVERIFIED`, `UNVERIFIED_SPECIFIC`, `OUTSIDE_HOURS`,
`HOTEL_MATCH_UNCERTAIN`, `PACING_CONFLICT`.

**Structural, client-computed (block):** `DAY_CITY_DISCONTINUITY`, `DUPLICATE_CHECKIN`,
`ORPHANED_TRANSITION`, `CITY_BACKTRACK`, `FLIGHT_TIME_MISMATCH`, `BOOKING_URL_IMPLAUSIBLE`.

**Structural, client-computed (warn/info):** `VEHICLE_STATE_CONFLICT`, `NIGHT_COUNT_MISMATCH`,
`WEEKDAY_CLAIM_MISMATCH`, `BOOKING_URL_DEAD`, `FLIGHT_UNVERIFIED`, `MEAL_POLICY_STRIP`,
`DUPLICATE_VENUE_SAME_DAY`, `DUPLICATE_ARRIVAL_STRIPPED`, `DRIVE_TIME_IMPLAUSIBLE` (needs
`TOMTOM_API_KEY`), `HOTEL_BRAND_UNCONFIRMED` (needs `TRIPADVISOR_API_KEY`),
`BUDGET_TOTAL_MISMATCH`, `COST_ESTIMATE_NIGHTS_MISMATCH`, `OVERCONFIDENT_LANGUAGE`,
`BUDGET_CEILING_EXCEEDED`.

Hotels are exempt from hours checks entirely (reception is 24/7; Places hours usually describe the
restaurant). A hotel with a block flag stays in the plan — an itinerary with no bed hides the
problem worse than showing it.
